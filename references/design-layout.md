# 设计与布局决策

## 用页面任务决定信息顺序

| 场景 | 优先回答 | 常见结构选择 | 最易误伤的做法 |
|---|---|---|---|
| B2B 制造商 | 供应什么、规格是否匹配、怎样联系 | 分类入口、真实产品/工艺、参数、证据与询盘 | 巨大宣传语把产品与采购信息推到数屏后 |
| 产品详情 | 型号、性能、适配条件、交付方式 | 图文并列、规格表、文件入口、询盘上下文 | 隐藏参数、虚构 MOQ/交期、把不同 SKU 混在一起 |
| SaaS/工具 | 能完成什么、如何开始 | 真实流程或界面、关键能力、操作入口 | 用静态假交互冒充可用功能 |
| 内容/教育 | 在哪一节、怎样持续阅读 | 受控行长、文章层级、目录与相关内容 | 正文过窄、过亮或每段加卡片 |
| 管理后台 | 当前状态、异常、下一步操作 | 筛选、表格、状态与就近操作 | 营销式巨大标题和空白降低操作效率 |

不要自动创建表中所有区块；保留当前任务确实需要且有事实支持的内容。

## 最小设计说明

在实现前记录：主要受众与动作、内容排序、沿用的品牌资产、字体角色、颜色角色、内容宽度、一个明确的视觉特征。小修只记录变动部分。无需另建整套设计文档。

如果用户给参考图/参考站，拆解其节奏、比例、层级和交互，再匹配当前内容。只有明确要求且具有使用权时才复用其专有素材；不要顺手复制公司名称、联系信息或结构化数据。

## 空间与网格

- 先决定正文与媒体的关系，再决定列数。12 列是一种选择；2–4 个实际网格区域通常已足够。
- 使用 `minmax(0, 1fr)` 与 `min-inline-size: 0` 解决内容最小宽度问题；不要先把页面溢出裁掉。
- 同级元素共享对齐线。同组间距小于组间距；正文中标题上方通常比下方留更多空间，但首个标题和紧凑表单可例外。
- 使用内容宽度和流式边距，避免超宽屏正文横跨整屏；导航与工具栏允许比正文更宽。
- 视觉顺序与 DOM 阅读顺序保持一致。不要用 CSS `order` 让键盘遍历和视觉位置脱节。
- 断点在内容开始拥挤处设置，并覆盖断点前后一像素的异常；无需为每种设备创建固定版本。
- 对窄侧栏、卡片内部等可复用上下文，可在父层声明 `container-type: inline-size`，让子层用 `@container`；不要查询元素自身尺寸来改变自身造成错误假设。
- 数据表格可以在有名称、可操作的局部区域横向滚动；非数据正文应重排。保留表头关系，别为“移动端无滚动”丢弃关键字段。

## 组件与互动

导航：当前位置可辨识；移动菜单按钮暴露展开状态，关闭后焦点回到合理位置。模态结构需要焦点管理与 Escape 关闭；非模态导航不用强制焦点陷阱。

按钮与链接：跳转用链接，执行动作使用按钮。禁用需要可理解的原因；请求中防止误触重复提交，但失败后允许恢复。

表单：实际 label 与控件关联；说明与错误通过适合的语义关联，错误不只改变边框色。输入可换行或扩展，不用固定高度容器隐藏提示。

异步内容：状态变化应对辅助技术可感知；避免对每次输入都播报长文本。加载状态保留布局空间；空状态说明如何继续。

动效：仅为位置或状态变化提供反馈；减少动态效果时可直接切换状态。减少动画不应禁用必要的加载反馈或破坏依赖动画事件的逻辑。

## 性能与维护

- 保留现有框架和已安装组件。一次排版修复不应迁移 CSS 框架或增加动画库。
- 图片提供宽高/比例与合适尺寸；在目标网络下观察真实布局跳动。不要把所有图片都设置高优先级。
- 只加载实际用到的字体字重/字形；检查外部字体失败后的替代字形和换行。
- Tailwind 项目使用现有版本的主题入口映射同一组语义 token。不要盲目套用其他主版本的配置文件。
- 用真实任务判断密度与留白是否合适，不以“所有页面风格相同”作为一致性目标。
