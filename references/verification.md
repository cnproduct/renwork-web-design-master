# 验收协议

按变更范围执行，记录真实证据。此协议覆盖常见前端风险，不是完整 WCAG 认证清单。

## 浏览器检查

先确认本地服务/API 可达，再诊断空白、登录或 `Failed to fetch`。优先使用当前环境已有浏览器工具与项目测试工具；没有浏览器时报告限制，不把源代码推测当作渲染结论。

1. 从真实页面与关键操作开始，等待必要的字体/内容加载后再截图。
2. 新页面通常检查 320、390、768、1440 CSS px 宽度；既有小修检查问题视口和相邻布局。记录实际视口、路由、状态与浏览器，不把截图数量当作质量。
3. 检查长标题、长 URL、真实中文/目标语言、空结果、错误提示和缺图 fallback；只检查实际存在的状态。
4. 200% 缩放验证文本、操作和提示不丢失；检查 320 CSS px 宽度重排。适用时在 1280px 起点做 400% 页面缩放；数据表格等必要二维内容可在局部滚动。
5. 仅用键盘完成核心动作。检查 Tab 顺序、焦点可见且不被覆盖、菜单/弹窗关闭与焦点返回、跳过重复导航的方式。
6. 用辅助技术或无障碍树抽查结构、控件名称、标签关联、错误和动态反馈。自动扫描不能代替这些检查。
7. 检查慢/失败字体加载、减少动态效果、关键链接、表单真实响应；若承诺暗色模式则同时检查，不自动添加新模式。

## 可量化门槛

| 项目 | 验证目标 | 注意 |
|---|---|---|
| 普通文字对比 | 至少 4.5:1 | 不能把 4.499 向上取整为通过 |
| 大文字对比 | 至少 3:1 | 大文字按 18pt 常规或 14pt 粗体门槛，约 24px / 18.67px |
| 必要控件边界/状态图形 | 与相邻色至少 3:1（适用时） | 结合实际识别所依赖的视觉信息判断 |
| 指针目标 | WCAG 2.2 AA 的 24×24 CSS px 或满足其间距/例外条件 | 对常用独立按钮，44px 可作更舒适的设计目标，不能混称 AA 最低要求 |
| 文本间距覆盖 | 行高 1.5、段距 2em、字距 .12em、词距 .16em 时不丢内容或功能 | 应用于支持相应间距的文字，避免固定高度与裁切 |
| 重排 | 320 CSS px 阅读宽度无非必要的双向滚动 | 区分页面溢出与必要二维数据 |

上述数字的规范来源见 [sources.md](sources.md)。透明度、渐变、图片叠字或滤镜需检查实际合成背景的最差区域，不能直接把原始 CSS 色值交给简单对比度工具后宣布通过。

## 构建与证据边界

- 跑项目已有且相关的构建、类型检查和测试；不为静态字号修改新增大型测试框架。
- 对行为变化保留最小回归检查。视觉变化用实际页面截图或现有视觉回归覆盖；不要写只检查类名存在的“行为测试”。
- 审查共享组件受影响的其他调用处，至少选一个不同内容长度或布局上下文。
- 发现问题时标注：页面/组件、视口与状态、观察结果、用户影响、最小修复、复测结果。
- 无障碍与关键操作缺陷优先；其次处理移动端断行和视觉层级；最后调整装饰。
- 页面 200、构建通过、截图正常、联系表单响应成功、邮箱实际收到、公开部署和搜索收录是不同结论，不能互相替代。

## 精简验收记录格式

```text
范围：路由 / 组件 / 提交
验证：命令与结果；浏览器 / 视口 / 状态；关键操作结果
发现：位置、触发条件、影响、修复与复测
未测：原因与剩余影响
外部状态：只有实际验证才报告部署/送达/收录
```

不强制汇总一个“设计分数”；未执行项保持未测，不用估计分数掩盖证据缺口。
